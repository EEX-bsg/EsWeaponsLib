# 公開面と互換性

EWLを更新すると、利用者の手元にある外部Modがその更新に巻き込まれます。Workshopは自動で更新されるので、
外部Modの作者が何もしていなくても壊れることがあります。このページは、何を「公開面」とし、どう変えてよいかの決まりです。

## 公開面

- XMLカスタムモジュールの名前と要素(`EwlWeapon`・`EwlBlockPhysics` と、その中の要素名・型・既定値・意味)
- C#の公開型とメンバー(`EWL.Api` と `EWL.Modules` のpublicなもの)
- 挙動のうち、文書に書いたもの

一覧はリポジトリ直下の `api-surface.txt` で、`tools/api-surface.ps1` でビルド済みのDLLから作ります。

## なぜ壊れるのか

- XML: ブロックのモジュールが1つでも読み込めない(必須要素が無い・型が合わない・未知のモジュールがある)と、
  そのブロックは**全部のモジュールを失います**。未知の要素は無視されます。
- C#: 公開メソッドのシグネチャを変えると、コンパイル済みの外部DLLは実行時に `MissingMethodException` などで失敗します。

## 規則

| 面 | 1.0以降 |
|---|---|
| XMLスキーマ | **追加だけ**。新しい要素は必ず既定値付き・省略可にする。名前を変えるときは旧名を別名として残す。削除は「読んでも無視する要素」にして行う |
| C#公開API | 破壊的変更はメジャー版だけ。できれば `[Obsolete]` で1つ前のマイナー版から予告する |
| 内部 | 自由に変えてよい(`internal` なので外から見えない) |
| アセンブリ版 | `AssemblyVersion` は `1.0.0.0` に固定する。ライブラリの版は `Mod.xml` の `Version` で表す |

1.0より前(α・β)は破壊的変更をしてよいですが、必ずCHANGELOGに「旧 → 新」の例を書きます。
未リリースの間は、利用側と同時に直すなら旧名の別名も要りません。

判断に使う問いは1つです: **「この変更で、既存のブロックXMLか、コンパイル済みの外部DLLが壊れるか」**。

## 公開面を変える手順

1. ビルドして `tools/api-surface.ps1` を実行し、`api-surface.txt` の差分を確認する。
2. 上の問いで判定する。
   - 壊れない: `CHANGELOG.md` の `[Unreleased]` に1行で追記する。
   - 壊れる: `[Breaking]` と書き、「旧 → 新」の具体例(XMLとC#の両方、該当するもの)を付ける。1.0以降はメジャー版を上げ、メンテナーの確認を得る。
3. `tools/gen-reference.ps1` を実行して `docs/reference/` を作り直す。
4. `api-surface.txt` と `docs/reference/` を変更と一緒にコミットする。

## 新しい要素・メンバーを足すとき

- 実在の利用者が必要としていることを確かめる。
- 内部 → `Api/` → (必要なら)`Modules/` の順に入れる。
- `Api/` の型・メンバーには `///` で説明を書く(単位・既定値の意味・「0なら無効」など)。リファレンスはここから作られます。
- XMLの要素名は対応するC#のフィールド名と同じにする。
- 任意機能はnullではなく「0なら無効」の既定値で表す。
