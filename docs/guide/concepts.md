# 基本の考え方

XML でも C# でも共通する、EWL を使う前に知っておくことです。

## 使い方は4段階

| 形態 | やること | ページ |
|---|---|---|
| A. XML だけ | ブロック XML に `EwlWeapon` などを書く | [最初の武装を作る](xml-first-weapon.md)、[XML の使い方](xml-recipes.md) |
| B. A + 観測 | C# で武装の残弾やイベントを読む(HUD など) | [C# で使う](csharp.md#武装を観測する) |
| C. 独自モジュール | 自分の C# モジュールから `Weapon` を作って駆動する | [C# で使う](csharp.md#自分のモジュールで武装を作る) |
| D. 独自機能 | 下位の部品とイベントで EWL に無い挙動を足す | 今後、必要に応じて公開します |

EWL 自身の `EwlWeapon` は形態 C と同じ公開 API だけで書かれています。XML でできることは C# でもできます。

## 依存のしかた

- EWL はタイトル画面で読み込まれるので、EWL を使う Mod より必ず先に読み込まれます。
- ブロック XML では、EWL のモジュールに `modid="0d219960-b202-4906-b29d-8d90a61a89b8"`(EWL の Mod ID)を付けます。
- C# から使うときは、EWL が入っていない環境も考えて `Mods.IsModLoaded` で確かめてから使います([C# で使う](csharp.md))。
- EWL を同梱して配布することはできません。利用者に EWL を別に導入してもらいます(Workshop のページで EWL を必須アイテムに指定しておくと親切です)。

## 定義は「武装」と「弾」

- **武装**(`EwlWeapon` / `WeaponSpec`): 発射位置・初速・間隔・弾数・弾倉・発射エフェクトなど、発射機そのものの値。
- **弾**(`Projectile` / `ProjectileSpec`): 弾の物理・コライダー・見た目・ダメージ・信管と、`Explosion`(爆発)・`Booster`(推進)・`Guidance`(誘導)。
- XML の要素名と C# のフィールド名は同じです(`EwlWeapon` 直下 = `WeaponSpec`、`EwlWeapon/Projectile` = `ProjectileSpec`)。
- 使わない機能は書かなければ無効です。爆発は `Radius` が 0、推進は `Thrust` が 0、誘導は `Gain` が 0 なら働きません。

## 実行権威

Besiege のマルチプレイでは、ホスト・クライアントのほかに、クライアントが自分だけでシミュレーションする「ローカルシミュレーション」があります。
EWL は「そのシミュレーションの物理をこのピアが担当しているか」(実行権威)で処理を分けます。

| 状況 | 発射・命中・ダメージ | 見た目 |
|---|---|---|
| SP | 自分 | 自分 |
| MP のグローバルシミュレーション | ホスト | クライアントは同期された見た目だけの弾を出す |
| MP のローカルシミュレーション | そのクライアント | 他のプレイヤーには見えない |

- `Weapon.TryFire()` などの要求は、実行権威のある側でだけ受け付けられます。それ以外では何もせず `false` を返します。
- 命中のイベント(`Weapon.Hit` / `Weapon.AnyHit`)も実行権威のある側でだけ発火します。
- 同期のためのコードを書く必要はありません。

## ライフサイクル

- 武装はシミュレーション開始で作られ、停止で外されます。
- 撃った武装が壊れたり外れたりしても、飛んでいる弾は最後まで飛びます。
- シミュレーションが止まると、弾とエフェクトはすべて回収されます。

## XML の再読込

ブロックを定義した Mod の `Mod.xml` が `<Debug>true</Debug>` のとき、ゲーム中にブロック XML を保存すると、
多くの要素は次のシミュレーション開始から反映されます。キー・トグル・スライダーの参照と `EwlBlockPhysics/AdditionalColliders` は
Besiege の再起動が必要です(どれが対象かは [XML リファレンス](../reference/xml-modules.md) の「再読込」列)。

## よくある失敗

| 症状 | 原因と対処 |
|---|---|
| ブロックの機能(EWL 以外も含めて)が全部効かない | ブロックのモジュールが1つでも読めないと、Besiege はそのブロックの全モジュールを捨てます。`output_log.txt` の警告を見て、必須要素(`EwlWeapon` の `FireKey`)、要素名の綴り、値の型を確かめてください |
| `EwlWeapon` が認識されない | `modid` の書き忘れ・誤り。EWL が有効か |
| 弾が自分のマシンに当たって爆発する | 発射位置をブロックの外に出すか、`Projectile/ColliderEnableDelay` を延ばす(初速の遅い弾は特に) |
| 撃てるが弾が見えない | `Projectile/Mesh` が無いときは小さな球です。メッシュ名は、ブロックを定義した Mod の `Mod.xml` の `Resources` に書いた名前を使います |
| エフェクトが出ない | `AssetBundle` の指定、プレハブ名の綴り。読み込み直後のシミュレーションでは、バンドルの読込完了後に差し込まれます |

## 版と互換性

EWL は 1.0 まで、公開面(要素名・C# API)を予告付きで変えることがあります。変更点と移行の例は [CHANGELOG.md](../../CHANGELOG.md) にあります。
1.0 以降は、既存のブロック XML や外部 DLL を壊す変更はメジャー版でだけ行います。
